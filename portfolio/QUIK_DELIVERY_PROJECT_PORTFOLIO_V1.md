## 2. 프로젝트 배경과 해결하려는 문제

실제 배송 업무에서는 한 건의 수입뿐 아니라 근무시간, 회사입금, 데이터사용료, 전기비, 통행료와 기타 비용을 함께 관리해야 합니다. 수기로 기록하면 기간별 합계를 다시 계산해야 하고, 기록이 없는 날짜의 고정비가 빠질 수 있습니다.

이를 해결하기 위해 기록 입력부터 월별 정산과 백업까지 하나의 Android 앱 흐름으로 구성했습니다.

## 3. 목표와 주요 요구사항

- 모바일에서 배송과 근무정보를 빠르게 기록
- 수입·비용·실수령액 자동 계산
- 오늘·주·월·연·전체 기준 조회
- 부가세와 달력 기반 분석
- 데이터가 없는 월도 포함한 12개월 정산
- 배송 0건 날짜의 고정비 누락 방지
- 기존 데이터 보존과 JSON 백업·복원

## 4. 시스템 구성

```text
사용자 입력
→ UI Controller
→ Manager
→ Repository
→ JsonFileService
→ Application.persistentDataPath

저장 데이터
→ Repository
→ Manager Summary
→ 홈 / 기록 / 통계 / 달력 / 정산
```

## 7. 사용 기술과 선택 이유

### Unity / C#

기존 교육과정에서 익힌 UI 구조와 C# 로직을 모바일 업무 앱으로 확장하고, 동일한 Scene에서 화면 전환과 데이터를 빠르게 검증하기 위해 사용했습니다.

### uGUI / TextMeshPro

모바일 세로 화면의 입력 필드, 버튼, ScrollView와 한글 텍스트를 구성했습니다.

### JSON

서버 없이 단일 사용자 기기에서 데이터를 단순하고 투명하게 저장·백업하기 위해 선택했습니다.

### NativeFilePicker / Android MediaStore

앱 내부 저장을 넘어 사용자가 백업 파일을 직접 내보내고 선택해 복원할 수 있도록 사용했습니다.

## 8. 핵심 구현 기능

### 배송 기록

날짜, 시간, 주소, 수입과 비용 항목을 입력하고 총수입·총비용·부가세·실수령액을 즉시 계산합니다. 고유 ID를 기준으로 기존 기록 수정과 삭제를 지원합니다.

### 근무 관리

근무 시작·종료와 오늘·월간 근무시간을 표시하며, 과거 날짜의 근무 시작·종료 시간도 수정할 수 있습니다.

### 기록·통계·달력

오늘·주간·월간·부가세 목록, 사용자 지정 날짜·금액 필터, 월간 달력과 주간 차트를 제공합니다.

### 월별 정산

선택 연도의 1월~12월을 항상 표시하며, 데이터가 없는 월도 0건·0원으로 유지합니다. 12개 카드는 2열 Grid로 구성했습니다.

### 백업

배송기록과 근무기록을 하나의 JSON으로 백업하고 Download 내보내기와 파일 선택 복원을 지원합니다.

## 9. 데이터 및 시스템 연동

외부 서버나 DB가 아닌 `Application.persistentDataPath`의 JSON을 사용합니다. UI는 Manager API만 호출하고 Repository가 목록 저장을 담당하도록 책임을 분리했습니다.

Android 위치 기능은 버튼 클릭 시 1회만 현재 좌표를 요청하며, Geocoder가 실패하면 좌표 문자열을 사용할 수 있도록 처리했습니다.

## 10. 대표 기술 문제와 해결 과정

### A. 배송 0건 날짜의 고정비 누락

**상황:** 배송을 등록한 날에만 고정비가 생성되어 기록이 없는 날짜의 비용이 빠졌습니다.  
**원인:** 생성 진입점이 배송 저장·수정 이벤트에만 연결되어 있었습니다.  
**해결:** 기준일부터 오늘까지 누락 날짜를 검사하고, `HashSet`으로 기존 날짜를 수집해 없는 날만 추가했습니다. 앱 시작·자정·복귀·백업 복원에서 같은 메서드를 호출했습니다.  
**결과:** 기존 레코드 변경 없이 누락분만 보정하며 중복 생성을 방지했습니다.  
**배운 점:** 날짜 기반 업무 규칙은 사용자 입력뿐 아니라 앱 생명주기까지 포함해 설계해야 합니다.

### B. 기존 데이터 보존

**상황:** 구형 JSON과 실사용 기록이 있는 상태에서 계산·보정 로직을 추가해야 했습니다.  
**원인:** 기존 레코드를 재계산하면 과거 값이 달라질 수 있었습니다.  
**해결:** 신규 고정비 레코드만 추가하고 Summary는 원본 객체를 수정하지 않는 방식으로 계산했습니다.  
**결과:** 새 기능과 기존 데이터 보존을 분리했습니다.

### C. 정산 UI 겹침

**상황:** 런타임 생성 월 카드와 백업 영역이 모바일 화면에서 겹쳤습니다.  
**원인:** 고정된 12개 카드까지 코드로 생성해 Edit Mode에서 배치를 조절하기 어려웠습니다.  
**해결:** 정산 패널만 Edit Mode 구조로 바꾸고 2열 Grid와 백업 토글을 Scene에 고정했습니다.  
**결과:** 다른 런타임 UI는 유지하면서 정산 화면만 쉽게 조정할 수 있게 됐습니다.

### D. Android 백업 접근

**상황:** 앱 내부 파일만으로는 기기 교체와 재설치에 대비하기 어려웠습니다.  
**해결:** 통합 백업, Download 내보내기, MediaStore 대체 경로, NativeFilePicker 복원을 구성했습니다.  
**결과:** 로컬 저장을 사용자가 직접 관리할 수 있는 백업 흐름으로 확장했습니다.

## 11. 성능 및 안정화

- 일일 누락 보정은 전체 기록을 한 번 로드하고 한 번 저장
- 같은 날짜 검사에 `HashSet` 사용
- 60초마다 파일을 읽지 않고 날짜 변경만 비교
- 재진입 플래그로 중복 경로 차단
- 반복 데이터 UI와 고정 UI의 생성 방식을 분리

대량 데이터에서는 JSON 전체 파일 재작성 비용이 증가할 수 있으며 향후 개선 항목으로 남겼습니다.

## 17. 면접용 30초 설명

Quik Delivery는 실제 배송 업무에서 배송기록, 근무시간, 수입과 비용, 월별 정산을 관리하기 위해 Unity로 만든 Android 개인 앱입니다. UI·Manager·Repository·JSON 계층을 나눠 기록 생성부터 복원까지 구현했고, 배송이 없는 날의 고정비가 누락되는 문제는 기존 데이터를 바꾸지 않고 누락 날짜만 보정하는 방식으로 해결했습니다.

## 18. 면접용 1분 설명

Quik Delivery는 제가 실제 배송 업무를 하면서 기록과 수익 계산을 편하게 관리하기 위해 만든 Unity Android 앱입니다. 배송 등록, 근무 시작·종료, 기록 수정·삭제, 기간별 통계, 달력, 부가세 조회, 연도별 월 정산과 JSON 백업을 구현했습니다. 가장 중요한 문제는 배송을 한 건도 등록하지 않은 날에는 회사입금과 데이터사용료 같은 일일 고정비가 생성되지 않아 월별 합계가 맞지 않았다는 점입니다. 이를 해결하기 위해 기준일부터 오늘까지 기존 고정비 날짜를 HashSet으로 수집하고, 누락된 날에만 별도 비용 레코드를 추가했습니다. 기존 기록은 재계산하거나 변경하지 않았고, 앱 실행과 자정, 포커스 복귀, 백업 복원에서도 같은 보정 로직을 사용해 중복을 막았습니다. 이 프로젝트를 통해 실사용 앱에서는 기능 수보다 데이터 보존과 정합성이 더 중요하다는 것을 배웠습니다.
