# 06. 데이터와 백업

## 저장 파일

| 파일 | 내용 |
|---|---|
| `delivery_records.json` | 배송·수입·비용 레코드 목록 |
| `work_sessions.json` | 근무 시작·종료 목록 |
| `app_settings.json` | 앱 설정 |
| `backup_*.json` | 배송·근무 통합 백업 |

실제 파일명 일부는 Inspector 설정에 따라 달라질 수 있으며, 모든 저장은 `Application.persistentDataPath`를 기준으로 합니다.

## DeliveryRecord 주요 필드

- 식별: `Id`, `WorkSessionId`
- 시간: `Date`, `StartTime`, `EndTime`
- 위치: 출발·도착 주소와 좌표
- 수입: 기본요금, 부가세 포함 입력, 추가요금
- 비용: 회사입금, 데이터사용료, 기타 차감, 전기비, 통행료
- 결과: 총수입, 총비용, 실수령액
- 상태: 정산 여부, 일일 고정비 여부

## 계산 기준

```text
총수입 = 기본요금 + 부가세 포함 입력값 + 추가요금
총비용 = 회사입금 + 데이터사용료 + 기타 차감 + 전기비 + 통행료
실수령액 = 총수입 - 총비용
```

`VatAmount`는 `BaseFeeVatSource`의 10%를 별도 조회용으로 계산하며 실수령액에서 다시 차감하지 않습니다.

## 일일 고정비 레코드

`IsDailyFixedExpense=true`인 별도 레코드로 저장합니다.

- 배송 건수: 제외
- 비용 합계: 포함
- 실수령액: 포함
- 날짜별 최대 1건
- 기존 사용자 레코드와 구분

## 백업 구조

```text
FullBackupData
├─ BackupCreatedAt
├─ BackupFileName
├─ DeliveryRecords[]
└─ WorkSessions[]
```

백업 파일명은 최초 데이터 날짜와 백업 날짜를 조합합니다. 복원 시 배송·근무 목록을 저장한 뒤 오늘까지의 누락 고정비를 보정합니다.

## 개인정보와 공개 기준

백업에는 실제 이동 지역, 메모, 수입·지출, 근무시간이 포함될 수 있습니다. 따라서 다음 원칙을 적용합니다.

- 실제 백업과 기록 JSON은 공개 Git에서 제외
- 화면 이미지는 테스트 데이터로 재촬영
- 주소, 메모, 실제 금액은 블러보다 테스트 값 교체를 우선
- APK와 서명 키도 저장소에서 제외

## 현재 저장 방식의 한계

- CRUD 때마다 전체 JSON 목록을 다시 씁니다.
- `File.WriteAllText` 직접 저장이며 임시 파일 교체 방식이 아닙니다.
- 데이터가 매우 커지면 저장 비용과 파일 손상 대응을 개선해야 합니다.

향후에는 임시파일 저장 후 교체, 백업 자동 회전, 데이터 버전 필드를 고려할 수 있습니다.
