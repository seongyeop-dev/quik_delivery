# 08. 회고와 개선

## 배운 점

### 실사용은 숨은 요구사항을 발견하게 한다

초기 기능 목록만으로는 배송 0건 날짜의 고정비 누락을 발견하기 어려웠습니다. 실제 데이터를 누적해 월별 합계를 확인하면서 업무 규칙과 코드 진입점이 맞지 않는 문제를 찾았습니다.

### 기존 데이터 보호가 새 기능보다 우선이다

운영 중인 앱은 계산 코드를 고치는 것만으로 끝나지 않습니다. 기존 JSON의 레코드를 다시 계산하지 않고 신규 보정 레코드만 추가하도록 범위를 제한하면서 업데이트 안정성의 중요성을 배웠습니다.

### UI 생성 방식은 화면 성격에 따라 달라야 한다

기록·부가세·달력처럼 데이터 개수가 변하는 화면은 런타임 생성이 적합했습니다. 반면 12개로 고정된 월별 카드는 Edit Mode 배치가 앵커와 가독성 조정에 유리했습니다.

## Known Issues

- JSON 전체 목록 재저장 구조
- 원자적 파일 저장 미적용
- 서버·클라우드 동기화 없음
- 단일 사용자와 로컬 기기 기준
- Android 업데이트 설치 및 데이터 유지 최종 검증 필요
- 일부 외부 에셋이 프로젝트 용량에 비해 과도함

## 저장소 최적화

업로드된 Assets 기준으로 다음 정리가 필요합니다.

- `Assets/Fonts/nanum-all_new.zip`: 약 131MB, 실행에 불필요하며 GitHub 단일 파일 제한을 초과할 수 있음
- `Assets/Image/CleanFlatIcon`: 약 455MB, 파일 12,273개
- CleanFlatIcon의 PNG 5,933개 중 Scene에서 확인된 참조는 `icon_activity_65.png` 1개
- TextMesh Pro Examples & Extras는 실제 앱에서 사용하지 않으면 제거 후보

에셋 삭제 전에는 사용 아이콘을 독립 폴더로 복사하고 Unity GUID 참조를 유지하거나 새 참조로 교체한 뒤 Missing Sprite 여부를 확인해야 합니다.

## 향후 개선

1. 임시파일 저장 후 원자적 교체
2. 백업 자동 회전과 복구 파일 보관
3. 데이터 스키마 버전과 마이그레이션 로그
4. 고정비 금액을 설정 화면에서 기간별 규칙으로 관리
5. Android 실기기 자동 회귀 체크리스트 정리
6. 테스트 데이터 모드와 포트폴리오 데모 빌드 분리
