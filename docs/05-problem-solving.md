# 05. 문제 해결

## 사례 1. 배송 0건 날짜의 비용 누락

### 상황

배송을 한 건 등록하면 해당 날짜에 회사입금과 데이터사용료가 자동 기록됐지만, 배송을 등록하지 않은 날에는 비용 레코드가 없었습니다. 월별 정산에서 날짜 수에 따라 발생해야 하는 비용이 빠졌습니다.

### 원인

고정비 생성 함수가 `SaveDeliveryRecord`와 `UpdateDeliveryRecord` 이후에만 호출되고 있었습니다. 앱 실행이나 날짜 변경 시 전체 기간을 보정하는 진입점이 없었습니다.

### 해결

- 기준일~오늘 사이 날짜를 반복
- 기존 `IsDailyFixedExpense` 날짜를 `HashSet<string>`으로 수집
- 없는 날짜만 신규 레코드 추가
- 신규 레코드가 하나 이상일 때만 `SaveAllRecords` 1회 호출
- 앱 시작, 60초 날짜 감시, 포커스 복귀, 일시정지 해제, 백업 복원에서 같은 보정 메서드 사용

### 결과

기존 배송기록은 그대로 두고 누락된 고정비만 추가할 수 있게 됐습니다. 여러 진입점이 같은 날 호출되더라도 날짜 집합과 재진입 플래그로 중복 생성을 막았습니다.

### 배운 점

자동 데이터 생성은 사용자 이벤트에만 의존하면 빠지는 상태가 생길 수 있습니다. 실제 업무 규칙이 ‘날짜 기준’이라면 앱 생명주기와 날짜 변경을 함께 고려해야 합니다.

## 사례 2. 기존 기록을 보존하는 소급 보정

### 상황

이미 실사용 기록이 저장된 앱에 누락 보정을 추가해야 했습니다. 기존 JSON을 새 형식으로 일괄 변환하거나 과거 값을 재계산하면 사용자 기록이 달라질 위험이 있었습니다.

### 원인

구형 백업에는 새 필드가 없을 수 있고, 계산 로직이 바뀐 뒤 기존 레코드 전체에 다시 적용하면 당시 입력값과 결과가 바뀔 수 있습니다.

### 해결

- 기존 레코드의 ID·날짜·금액·메모를 수정하지 않음
- 새 고정비 레코드만 추가
- Summary 계산은 원본 객체에 값을 다시 쓰지 않고 지역 변수로 집계
- 백업 원본은 변경하지 않고 복원된 로컬 목록에만 보정 적용

### 결과

업데이트 기능 추가와 데이터 보존을 분리했습니다. 포트폴리오에서도 ‘마이그레이션’이 아니라 ‘누락 항목 추가형 보정’으로 정확히 설명할 수 있습니다.

## 사례 3. 정산 런타임 UI의 앵커와 가독성

### 상황

월별 카드와 백업 메뉴를 런타임으로 생성했을 때 제목, 버튼, 백업 영역이 서로 겹치고 카드 간격을 조정하기 어려웠습니다.

### 원인

모바일 세로 해상도에서 반복 UI의 크기와 앵커를 코드 값만으로 맞추고 있어 Edit Mode에서 최종 배치를 확인하기 어려웠습니다.

### 해결

- 변경 범위를 `SettlementPanel`로 제한
- 정산만 Edit Mode 구조로 전환
- `HeaderRow`, `ActionRow`, `Panel_Backup`, `Grid_MonthCards` 구성
- 월 카드 12개를 2열 고정 Grid로 배치
- 다른 패널의 부가세·기록 런타임 생성은 유지

### 결과

정산 UI는 Inspector에서 쉽게 미세조정할 수 있고, 다른 패널의 기존 동작에는 영향을 주지 않는 구조가 됐습니다.

## 사례 4. Android 백업 파일 접근

### 상황

앱 내부 백업만으로는 기기 교체나 재설치에 대비하기 어렵고, 최신 Android에서는 Download 폴더 직접 쓰기만으로 호환성을 보장하기 어렵습니다.

### 해결

- 앱 내부 백업 생성
- 직접 파일 복사를 먼저 시도
- Android에서는 MediaStore 대체 저장 경로 제공
- NativeFilePicker로 사용자가 `backup_*.json`을 직접 선택
- 파일명과 데이터 구조를 검사한 뒤 복원

### 결과

로컬 앱의 단순 JSON 저장을 기기 외부 백업·복원 흐름으로 확장했습니다.
