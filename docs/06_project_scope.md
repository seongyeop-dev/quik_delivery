# 06. Project Scope

## 주요 문제와 해결

| 문제 | 원인 | 해결 방법 | 결과 |
|:---|:---|:---|:---|
| 배송이 없는 날짜의 일일 고정비 누락 | 배송 기록이 생성된 날짜를 중심으로 비용 데이터가 존재함 | 기준 시작일부터 오늘까지 날짜를 순회하고 `IsDailyFixedExpense` 레코드가 없는 날짜에 고정비 생성 | 앱을 실행하지 않았던 날짜의 고정비도 통계와 정산에 반영 |
| 일일 고정비가 배송 건수에 포함됨 | 배송과 고정비가 같은 `DeliveryRecord` 목록에서 집계됨 | `IsDailyFixedExpense`로 레코드 종류를 구분하고 실제 배송 판정에서 제외 | 비용과 실수령은 유지하면서 배송 건수 통계의 의미를 분리 |
| 배송 데이터 변경 후 화면별 값이 달라짐 | 홈·기록·통계·캘린더·정산이 같은 데이터에 의존하지만 갱신 시점이 다름 | 생성·수정·삭제와 복원 이후 연결된 UI의 갱신 메서드를 호출 | 주요 화면이 저장된 최신 데이터 기준으로 일치 |
| 월별 정산 UI 구성 요소가 겹침 | 런타임 생성과 레이아웃·Inspector 참조 설정이 한 과정에 섞임 | `SettlementPanelEditModeBuilder`로 레이아웃과 참조를 구성하고 12개 `MonthlySummaryCardUI`를 고정 | Edit Mode 기준의 1월~12월 카드 배치와 연도별 갱신 구조 확보 |
| Android 백업 저장 위치와 접근 방식이 다름 | 앱 내부 저장소, 다운로드 폴더와 파일 선택창이 서로 다른 경로를 사용함 | 내부 백업 생성, 최신 백업 다운로드 내보내기와 파일 선택 복원을 각각 분리 | Android 실기기에서 백업 생성·내보내기·복원 흐름 확인 |
| 복원 데이터에 누락 고정비가 존재할 수 있음 | 백업 생성 시점 이후 날짜 또는 과거 누락일이 복원 데이터에 포함되지 않을 수 있음 | 배송·근무 데이터 저장 후 `EnsureMissingDailyFixedExpenses`를 다시 실행 | 복원 후 오늘까지의 고정비와 정산 기준을 다시 맞춤 |

## 최종 구현 범위

| 영역 | 최종 구현 내용 |
|:---|:---|
| 앱 실행 | `MainScene` 기반 Android 모바일 앱 |
| 배송 관리 | 배송 기록 생성·조회·수정·삭제와 수입·비용·부가세·실수령 계산 |
| 근무 관리 | 근무 시작·종료, 저장과 날짜·시간 수동 보정 |
| 기록 조회 | 오늘·주간·월간 기록과 부가세 대상 기록 조회 |
| 통계 | 오늘·주간·월간·연간·전체·직접 기간 및 최소·최대 금액 필터 |
| 캘린더 | 날짜별 근무시간·배송 건수·수입·비용·실수령·부가세와 주간 차트 |
| 월별 정산 | 이전·다음 연도 이동과 1월부터 12월까지의 고정 월별 카드 |
| 일일 고정비 | 기준 시작일부터 오늘까지 누락된 고정비 생성 및 배송 건수 분리 |
| 데이터 저장 | `delivery_records.json`, `work_sessions.json`, `app_settings.json` |
| 백업·복원 | `backup_*.json` 생성, Android 다운로드 내보내기와 파일 선택 복원 |
| 설정 | 위치 자동 입력, 글자 크기와 삭제 확인 설정 |
| 검증 | Unity Play Mode와 Android 실기기 주요 사용 흐름 검증 |
| 공개 자료 | 비식별화한 화면, 시연 영상과 데이터 처리 구조 문서 |

실제 배송 주소, 개인 메모, 수입 원본 데이터, 백업 JSON, APK 파일과 Android 서명 정보는 공개 저장소에 포함하지 않습니다.
