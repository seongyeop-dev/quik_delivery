# 01. 프로젝트 개요

## 개발 배경

배달 업무 기록은 배송 건수만으로 관리하기 어렵습니다. 근무시간, 기본 요금과 추가 요금, 회사 입금·데이터 이용료·통행료·충전비 등의 비용, 부가세와 월별 정산을 함께 확인해야 합니다.

기존 메모나 스프레드시트 방식에서 발생할 수 있는 반복 입력과 누락을 줄이고, Android 기기에서 배송 기록부터 정산과 백업까지 하나의 흐름으로 관리하기 위해 Unity 기반 모바일 앱으로 구성했습니다.

## 프로젝트 목적

- 배송 기록 생성·조회·수정·삭제
- 수입·비용·부가세·실수령 계산
- 근무 시작·종료와 날짜·시간 수동 보정
- 기간별 통계와 월간 캘린더 분석
- 이전·다음 연도 전환과 1월부터 12월까지의 월별 정산
- 배송이 없는 날짜의 일일 고정비 누락 방지
- JSON 전체 백업·복원과 Android 다운로드 폴더 내보내기
- Android 실기기 설치와 주요 기능 흐름 검증

## 구현 범위

| 영역 | 구현 내용 |
|:---|:---|
| Home | 오늘·이번 달·전체 요약, 근무 상태와 최근 배송 기록 표시 |
| Delivery | 배송 정보 입력, 수입·비용 계산, 기록 생성·수정·삭제 |
| Records | 오늘·주간·월간 배송 기록과 부가세 대상 기록 조회 |
| Stats | 오늘·주간·월간·연간·전체·직접 기간 및 금액 조건 통계 |
| Calendar | 날짜별 근무시간·배송 건수·수입·비용·실수령·부가세 표시 |
| Settlement | 이전·다음 연도 이동과 고정된 12개 월별 정산 카드 |
| Fixed Expense | 기준 시작일부터 오늘까지 누락된 일일 고정비 레코드 생성 |
| Backup | 전체 백업 생성, 다운로드 폴더 내보내기와 파일 선택 복원 |
| Settings | 위치 자동 입력, 글자 크기와 삭제 확인 설정 |

## 개발 단계

1. 실제 배달 업무에서 필요한 배송·근무·비용·부가세·정산 항목을 정의했습니다.
2. `DeliveryRecord`, `WorkSession`, `SettlementRecord`, `AppSettings`를 기준으로 데이터 구조를 구성했습니다.
3. JSON 저장 계층과 수입·비용 계산 서비스를 분리한 뒤 배송·근무 관리 기능을 구현했습니다.
4. 통계, 캘린더, 부가세 조회와 연도별 12개월 정산 화면을 연결했습니다.
5. 배송이 없는 날짜의 고정비 누락과 배송 건수 혼입 문제를 분리 처리했습니다.
6. 전체 백업·복원과 Android 다운로드 내보내기를 적용하고 실기기에서 주요 흐름을 검증했습니다.

## 최종 결과

`MainScene`을 중심으로 배송 기록, 근무시간, 통계, 캘린더, 부가세, 연도별 월 정산과 백업·복원 기능을 하나의 Android 앱에 통합했습니다.

누락된 일일 고정비를 기준 시작일부터 오늘까지 보정하면서도 실제 배송 건수에서는 제외하도록 집계 기준을 분리했습니다. 배송 기록과 근무 세션은 기기 내부 JSON 파일로 유지하며, 전체 백업 생성·내보내기·복원 흐름을 Android 실기기에서 확인했습니다.
